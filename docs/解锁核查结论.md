# Galaxy S23 SM-S9110 解锁核查

2026-11-07 更新；实机精确固件 S9110ZCS8FZI1 / CHC / Android 16 / One UI 8.5。

**结论：当前原厂固件主动关闭了正常 OEM 解锁入口。尚不能刷入 HakiOS，也没有完成可用驱动移植。**

## 为什么不是按键时长问题

用户从关机双音量插线的 Warning 页持续按住音量上超过30秒，按下瞬间就进入 Download Mode，没有确认页；普通与维护模式均一样。

对从三星官方 FUS 取得的精确 BL 做静态核查，发现调用链：

```text
Warning 处理
  → OEM 界面资格函数（RVA 0xcac60）
  → 唯一正常返回路径固定 w0=0
  → 调用方跳过长按检测
  → 未到达设备解锁界面（调用 RVA 0x7085c）
```

该函数仍读取并打印 OEM 状态，但正常返回值恒为0。详细指令、镜像 SHA256 和范围见 `abl-oem-gate-audit.json`。
Warning 页印有长按说明，只证明图片/文案保留，不能证明代码入口可达。

## 为什么 Android 中没有 OEM 开关

- 正常和维护模式实机均为 `ro.boot.other.locked=1`。
- 本机 SecSettings.apk 中 `OemUnlockPreferenceController.isAvailable()` 对该值等于1时直接返回 false。
- 同版 ABL 主模块含 `androidboot.other.locked=1` 及代码引用，与实机属性和菜单行为一致。
- 仅修改 Android 菜单不能解除引导器签名检查和实际准入条件。

## 尚未完成

手机未解锁、未擦除、未刷写，Knox在最后一次ADB读取及维护模式下载页照片中为0。
退出维护模式后已由ADB复核：主用户0、同版FZI1、引导仍锁定、Knox=0；临时USB常亮设置已恢复0。详见device-restored.json。
退出维护模式时设的临时锁屏由用户自己管理，未收集密码。

当前没有本型号本引导代际可复现的正常解锁替代路线。公开官方历史未找到 binary 8 的 Android 15；不能拿 S911B 或 dm2q 的方案混用。
现已取得并校验完整同版恢复包；此前“整套仍未下载”的状态已结束。详见 `stock-recovery-verification.json`。
但没有进行恢复刷写验收，恢复资料就绪也不改变启动链锁定。

CHC 最早公开 B8/FZE3 与港版 TGY B8/FZI1 的官方 BL 只读对照也显示同一正常资格门控返回 0，并含 other.locked=1。不能建议通过回退最早 B8 或刷港版来恢复该入口；未执行这两种刷写。

## 下一阶段的必要条件

第一项是取得可验证、适用于本机签名启动链的解锁/开发准入途径。没有这一项，继续编写显示、触控、GPU驱动也无法在本机运行验收。
本次静态分析不证明所有未来研究路线不可能，也没有生成能绕过签名的补丁。
用户清出的约61GB空间已用于完整恢复材料和设备树准备；二者均已完成本轮文件校验。下载解析后主机约29GiB可用。
静态树已按实机选择合并，复现步骤和驱动差异已入库；实机 UEFI、XNU 和驱动验收仍以解决引导准入为前提。
