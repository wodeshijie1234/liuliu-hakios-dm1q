# 原厂设备树的离线复现

本流程只处理主机上的原厂文件，不与手机通信。适用精确版本 SM-S9110 / CHC / S9110ZCS8FZI1。不同版本、机型或板修订必须重新确认选择，不能复用固定 index。

完整包从 Samsung FUS 通过 samloader 取得，版本、五包名称、SHA256、ZIP CRC 和附加 MD5 结果见 [stock-recovery-verification.json](stock-recovery-verification.json)。原始文件由研究者自行合法取得，不随本仓库分发。

## 1. 校验并提取小型资产

完整解密 ZIP 的 SHA256 为 `7cfe4cca0ea711e7371224e62fcfeed458ecf14b4f0a8c53792c0f8ed3fb5385`，13,811,659,536 字节。服务器加密包比它多 16 字节，属于本次加密填充长度差，不是下载缺失。

解包时逐个读取完 ZIP 成员以检查 CRC，再用已核验的 samloader 2.2.0 `verify-md5` 检查每个 tar.md5，另计算 SHA256。不要将下载元数据或 MD5 等同于厂商签名认证。完整包和五包均保留在私有工作目录，未进行回刷测试。

从已校验的 AP 中只读取 `vendor_boot.img.lz4`、`dtbo.img.lz4` 等小型资产并用 LZ4 解压；不必展开 super/userdata。此次关键资产：

| 文件 | 解压字节数 | SHA256 |
|---|---:|---|
| vendor_boot.img | 100663296 | c20fcf30062bcb44c14ec851bb1d938159179576331adf8faa767c11a5a6f8a5 |
| dtbo.img | 16777216 | ce5cd266686b0e939fc5c8cb147a1b8751b96e8e5e7a21bc630e31b737abc3d7 |

## 2. 拆出 base DTB 与 overlay

用 AOSP 的 [unpack_bootimg.py](https://android.googlesource.com/platform/system/tools/mkbootimg/+/refs/heads/main/unpack_bootimg.py) 解析 vendor_boot header v4。本轮使用文件 SHA256 为 `a9d260978a63bd06a24b6347e7dee8a28ff96639793caea15dff6aa491316308`，上游 main 可变化，复现需核对版本。

以下命令在本任务根目录运行，中间文件位于私有 work。它会解出 vendor ramdisk 等文件，不能直接复制整个目录到公共仓库。

```sh
python3 work/tools/aosp-unpack_bootimg.py \
  --boot_img work/stock-firmware/FZI1/boot-assets/vendor_boot.img \
  --out work/device-firmware/vendor-boot-unpacked
```

输出 dtb 是四个 FDT 顺序拼接。逐个按大端 magic `0xd00dfeed` 和 totalsize 遍历，所有边界都应落在文件内。实机只读属性 `ro.boot.dtb_idx=0`，取第0项（offset 0，452819 字节），SHA256 为 `fd484ce4b3581cc50c51dcf9119a5fbff05129aa075182b66c2e0a4474a94a02`。其他项见 base-dtb-summary.json。

dtbo.img 使用大端 DT table header，magic `0xd7b7ab1e`；本次 header/entry 各32字节、7项，条目表 offset32。每条目的前两个 u32 为 overlay 大小和文件 offset，必须验证索引和范围，再按 offset/size 截取。

实机 `ro.boot.dtbo_idx=6`、revision14，取第6项（1018457字节），SHA256 为 `4726b3e1d7dfc641f9a75afdf8371665c73977d5679a8fef755546326f755d16`。该项 model 是 Samsung DM1Q PROJECT (board-id,11)，hw_rev 范围11..32覆盖本机14。板号11与 Android revision14不是同一个字段，不能要求数值相等。

## 3. 合并并核对

本轮使用 dtc 固定提交 `54e547173bf0f2a4cc35eba8b5738caf38b9230f` 的 libfdt/fdtoverlay。macOS 动态版本曾缺 libfdt dylib，实际成功命令使用静态链接版本：

```sh
work/tools/fdtoverlay-static \
  -i work/device-firmware/vendor-boot-unpacked/base-index0.dtb \
  -o work/device-firmware/merged-dm1q-fzi1.dtb \
  work/device-firmware/ap-prefix/unpacked/dtbo-selected-index6.dtb
work/tools/dtc-src/dtc -I dtb -O dts \
  -o work/device-firmware/merged-dm1q-fzi1.dts \
  work/device-firmware/merged-dm1q-fzi1.dtb
```

最后一个输入路径保留了前部暂存提取的历史目录名；完整 AP 校验后已重新提取 dtbo 并核对相同 SHA256，见 provisional-recheck.json。复现时可以把自己截取的 overlay6 放到同一路径。

合并结果 SHA256：`d7daddc3aab38776fdb1350cb000f127d83a9547e2fe31cd10b89d2a74c54a29`。model 仍保留基础 Kalama v2 名称属于本次合并结果；不能仅凭 model 没变就认定 overlay 未应用。

## 4. 仅生成研究参数

```sh
python3 work/upstream/full/hakios-xnu-kernel-63fc2b4633bac3af8e57dadab9f5a8d4cb940438/tools/new-device.py \
  dm1q --fdt work/device-firmware/merged-dm1q-fzi1.dtb \
  --out work/dm1q-fdt-analysis-reproduction
```

工具找到12/16参数，但缺三个内存参数属于命名不兼容，IPA又含固定偏移假设，见 [驱动适配清单.md](驱动适配清单.md)。本次上游 redwood 参考 DTB 不在源码包中，没有完成工具宣称的两树比较，不把“生成成功”当作参数正确。

**停止点：不要复制生成的 soc.args 到运行配置，不要刷入上述 DTB/EFI。** 这是原厂静态树，未包含 ABL 运行时 fixup；目前也没有本机可执行的自定义启动准入或硬件验证。
